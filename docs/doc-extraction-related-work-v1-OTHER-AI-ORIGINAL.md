# 文档抽取 agent：成本 vs 准确率 — 相关工作扫描

2026-11-02 · 快速扫描（不是系统综述），主要查 2025–2026 年 arXiv / ACL

## 结论先说

- **有人做过，但都不完整。** 这些工作要么用公司内部数据（别人没法复现），要么只报准确率、不报美元成本，要么只看某一种方法，没有在"花一样多钱"的前提下公平比较几种做法。
- **重叠最大的一篇**是 Kulkarni & Kulkarni 2026（arXiv 2603.22651）。它比较了 4 种多 agent 架构的成本和准确率，但用的是自建的 SEC 文件数据，标注没有公开，也没有"一次抽取 + 自检"、"便宜模型先做、没把握再交给贵模型"这类对照。
- **我们的空白**：在**公开数据集**上，**按相同花费**公平比较"一次抽取 / 自检 / 多模型互相核对 / 先便宜后升级"这几种做法，画出成本–准确率曲线（Pareto 前沿），并分析出错类型。可以接上你会的校准：用校准后的信心决定什么时候升级到贵模型或交给人。

## 已有工作

| 论文 | 数据（是否公开） | 比较了什么 | 有没有报成本 | 和我们的重叠 |
|---|---|---|---|---|
| **Benchmarking Multi-Agent LLM Architectures for Financial Document Processing**（Kulkarni & Kulkarni, 2026, [arXiv 2603.22651](https://arxiv.org/abs/2603.22651)） | 1 万份 SEC 文件，25 个字段（标注未公开） | 4 种架构：顺序流水线 / 并行合并 / 主管-工人 / 自我纠错循环；5 个模型 | 有：每份文档成本、延迟。自我纠错 F1 0.943，成本 2.3 倍；主管-工人 F1 0.921，成本 1.4 倍 | **高**。最接近，但数据没法复现，没有一次抽取和升级策略的对照，也没有出错类型分析 |
| **Agentic System with RL Subsystem Improvements for Form-Like Documents**（Amjad 等, AAMAS-EMAS 2025, [arXiv 2505.13504](https://arxiv.org/pdf/2505.13504v1)） | CORD、SROIE（公开）+ 大量私有数据 | 一次抽取 vs 多 agent + 强化学习改 prompt；GPT-4o-mini | 只有时间（≥1 分钟 vs <10 秒），没有美元 | 中。证明 agent 在 CORD/SROIE 上更准（F1 0.886→0.965），但没算花多少钱 |
| **OCR or Not?**（SAP + Stanford, 2026, [arXiv 2603.02789](https://arxiv.org/html/2603.02789)） | 约 1,000 份内部商业文档（不公开） | 只给图片 / 只给 OCR 文本 / 图片 + OCR；约 10 个多模态模型；自动出错类型分析 | 有：每页成本和延迟估计 | 中。比较的是输入方式，没做自检或多 agent。作者自己说没试自我反思 |
| **Calibrated Confidence for Straight-Through Processing**（OCBC, 2026, [arXiv 2609.20110](https://arxiv.org/pdf/2609.20110)） | DocILE、FATURA、VRDU（公开） | 字段级信心 + 保证错误率的阈值（conformal），两个模型交叉核对 | 没有美元，只讲多少字段能自动通过 | 中。做的是"什么时候交给人"，不是成本–准确率比较。可以当信心部分的强基线 |
| **EXTRACTCONF: Beyond Logprobs**（Perfios, 2026, [arXiv 2606.24420](https://arxiv.org/pdf/2606.24420)） | DocILE、CORD（公开） | 两次不同方式调用 + OCR 等特征融合估信心；isotonic 校准 | 只说调用次数（2 次 vs 自洽采样 5 次） | 中。同上，只用了一个模型（GPT-4o） |
| **MADP**（2026, [arXiv 2605.17159](https://arxiv.org/abs/2605.17159)） | 955 份生产文档（不公开） | 5 个 agent 的流水线 + 人工复核 | 讲人力和碳排放，没有美元 | 低 |
| **Double Triangle Annotation**（EPFL, [ACL 2026 Findings / arXiv 2605.25781](https://arxiv.org/html/2605.25781)） | 历史文档（作者公开了基准） | 两个模型互相核对，不一致的交给人 | 只算人工复核比例 | 低–中。"两个模型一致就自动接受"的思路可以借用 |
| **Invoice IE: Methods and Evaluation**（2025, [arXiv 2510.15727](https://arxiv.org/pdf/2510.15727)） | 102 张发票 | Docling vs LlamaExtract | 只有时间 | 低。规模小 |
| **MuDABench**（[ACL 2026 Findings](https://aclanthology.org/2026.findings-acl.341.pdf)） | 跨文档财报问答 | RAG vs 多 agent 工作流 | 没有 | 低。但它的发现可以引用：单文档抽取的准确率是瓶颈 |

## 我们能做的新东西（按价值排序）

1. **相同花费下的公平比较**：同样花 $X，是用便宜模型 + 自检好，还是贵模型一次抽取好？现有工作都没有回答这个问题。
2. **先便宜后升级（cascade）**：便宜模型先抽，用校准过的信心判断没把握的字段，再交给贵模型或人工。这是你的强项，也是 2603.22651 没做的。
3. **全部用公开数据，可复现**：CORD、SROIE、FUNSD、DocILE、VRDU 或 Kleister。公开代码、公开所有模型输出。
4. **出错类型分析**：自检到底修好了哪类错，比如 OCR 认错字、选错字段、格式不对、凭空编造？哪类错自检修不好？
5. **多家模型**：便宜和前沿的闭源模型，加上开源模型。现有工作大多只用 1–2 个模型。

## 风险

- 偏工程，顶会主会可能会说"没有新方法"。所以要靠扎实的公平比较和 cascade + 校准这两点撑住。比较适合 workshop、ICDAR、应用类会议（KDD 应用数据科学 track、EMNLP 行业 track）。
- 2603.22651 一定要正面引用，并说明区别：公开数据、相同花费的比较、cascade。
- 预算：公开测试集加起来约 1,000–1,500 份文档 × 约 6 个模型 × 4–5 种做法。按便宜模型每份 $0.002–0.03 粗算，大约 $100–300，在 $500 上限内。开跑前要小样本实测。
